### 6301 — 生成（按分仮定つき）

優先順位1（会社開示の金融部門負債）は**取得できなかった**。有報にリテールファイナンス事業の

優先順位2の按分を適用した:

```
按分率 = リテールファイナンスのセグメント資産 1,617,867 ÷ 連結総資産 6,423,941 = 25.184%
連結純有利子負債 = 有利子負債 1,341,031 − 現金及び現金同等物 439,701 = 901,330
金融部門     = 901,330 × 25.184% = 226,992
事業側 net_debt = 901,330 − 226,992 + 非支配持分 197,659 = 871,989
金融事業価値   = 1,617,867 − 226,992 = 1,390,867（1株 1,544 円）
```

事業のみDCF: 連結 − リテールファイナンス = 売上 **4,006,614** / 営業利益 **530,735**
（連結 4,132,751 / 567,323 − 126,137 / 36,588）。Comps は PER/PBR 参照（型F 機構を流用）。

> **⚠ WARN（按分仮定）**: この値は金融債権に対する自己資本比率 **86%** を含意する。
> 販売金融会社の実勢は 10〜15% であり、資産比の按分は金融部門の負債を**過少**に、
> したがって金融事業価値を**過大**に見積もる。按分率・算式・根拠・限界は overrides の
> `_debt_allocation_WARN` と Adjustments Log に記録した。会社開示が得られたら差し替えること。

## 6. 検出・修正した不具合（本セッション最大の発見）

### 行挿入で Executive Summary の数式・値が消えていた ——— 真因は **結合セル**

症状は「`Comps - EV/EBITDA Median` のセルが空になる」。原因を3段階で追った。

1. 当初は openpyxl の**共有数式（shared formula）**の取りこぼしを疑い、挿入前後で数式を控えて
   書き戻す修正を入れた → **効かなかった**（メモリ上は書けているのに保存後に消える）。
2. 生の XML を見ると `<f>'Comps Analysis'!C27</f>` は**残っていた**。しかし openpyxl で
   読み直すと None、Excel で再計算すると本当に消えた。
3. **真因は MergedCell** —— `insert_rows` で行がずれると、上にあった結合セル（注記行の B:C 結合）が
   別の行に被さる。被った側は `MergedCell` になり、**openpyxl は書き込みを黙って捨てる**
   （`'MergedCell' object attribute 'value' is read-only` が最終的に例外として表に出た）。

**しかも `check 20` は空セルを「テキスト＝意図的に除外された手法」と読んで PASS していた。**
影響範囲は行を挿入する全モデル ——
型F 6件（8001/8002/8031/8053/8058/6971）・型E 2件（9434/4689）・型D 1件（8410）の
**9件すべてで見逃されていた**。

対処:

| 対象 | 対処 |
|---|---|
| `equity_method_value.py` | **行の挿入をやめた**。加算脚は Valuation Summary 下の空き行に書き、フロア規則は Target 式に `=MAX(0,IFERROR((<コア式>)*1,0))+C{加算行}` として畳み込む |
| `ddm_ri.py` | 型D は 2 行必要なので挿入は残し、**挿入直後に C 列にかかる結合を解除**してから書く |
| `validate_output.py` check 20 | **空セルを FAIL に**（除外は N/A と書く約束であり、空は数式が失われた疑い）。併せて comps 行を**ラベル解決**に変更（行番号決め打ちが誤読の温床だった） |
| `validate_output.py` check 26 | コアは独立行に無くなったので **Target − 加算脚**で導く |

## 1. 型トリアージ — **機能した。ただし事前分類は当てにならない**

- **9433 KDDI を型E として差し戻せたことが最大の成果**。§1-1 は「型C/D/E は意図的に除外済み」と述べていたが、EDINET 有報 XBRL（docID S100YKG2）の連結BSに `ShortTermLoansForFinancialBusinessCAIFRS` / `ShortTermDepositsForFinancialBusinessCLIFRS` 等の**金融事業専用科目**が存在し、金融事業の貸出金 6,398,477百万円（総資産の33.6%）・預金 5,666,952百万円（負債の42.1%）を確認した。auじぶん銀行・au損害保険を連結。**一次ソースでの検証が事前情報を覆した**。
- **7974 任天堂を型A→型B に修正**。機械ルール（OPMレンジ 16.07pt > 12pt）が正しく作動し、Switch 2 立ち上げ年（OPM 15.57%）を「一過性の落ち込み」ではなく「サイクルの谷」として扱えた。
- **9022 JR東海は逆に、機械ルールが型B を示したが型A に据え置いた**（OPMレンジ 14.6pt）。要因がサイクルではなくコロナ回復の単調過程だったため。**機械ルールの出力を無検討で受け入れない運用が必要**であることの実例。

### 改善: 残り銘柄に適用する追加チェック

EDINET XBRL の要素名に `ForFinancialBusiness` / `Deposits` / `CallLoan` / `Banking` が現れるかを**生成前に機械チェック**する。KDDI は事前トリアージ（財務比率のみ）では検出できず、XBRL を見て初めて確定した。同種の見落としが NTT（9432）等に残っている可能性がある。

## 2. size_premium バンド — **機械決定は動いたが、90銘柄すべてで同じ値になる**

- **全90銘柄の時価総額が3,000億円を超える**ため、§4-1 のバンドは**例外なく 1.0%** を返す。バンドが5段階ある意味が本リストでは失われている（§1-1 の「大半が1〜2%になるのが正常」という想定より更に一様）。
- より重要な問題として、**テンプレートの自動規則（≥1兆円 → 0.0%、≥1,000億円 → 1.5%）と食い違う**。信越化学（10.5兆円）で本仕様は 1.0%、テンプレは 0.0%。明示指定によりテンプレ値を上書きしているが、**WACC を全銘柄で 1.0pt 押し上げている**。
- rf 2.97%（実勢）+ ERP 6.5%（固定）+ size premium 1.0% の組み合わせで、**無借金・低ベータでない銘柄の Ke は 10%超**になる。4063 で 10.86%、7974 で 10.47%。これは日本株の実務水準としては高く、**バッチ全体が構造的に SELL 寄りに出る要因**になっている。→ バッチ最終レポートで報告。

## 3. beta の扱い — **仕様とテンプレの矛盾を発見。仕様どおりに書くと無言で壊れる**

§4-1 は「0.4未満は0.4、1.8超は1.8にクリップ」と指示するが、**テンプレートは beta を [0.6, 1.75] にクランプし、範囲外を無言で 1.0 に置換する**（`templates/dcf_comps_template.py:1819`、生成ログでも `Beta 0.372 outside [0.6, 1.5] range - using fallback 1.0` と確認）。

- 仕様どおり 0.4 を書けば **1.0 に置換され、低ベータ銘柄の WACC が 2〜4pt 跳ね上がる**。これはまさに §0 が禁じる「サイレントフォールバック」に該当する。
- **採用した運用**: `beta = max(0.6, min(1.75, 実測))`。2802（実測 0.372）と 9022（実測 0.165）で下限 0.60 を明示指定した。**§0「食い違えばスキーマ/実装が勝つ」に従った処理**であり、バッチ最終レポートで報告する。
- **7974 は yfinance が beta を返さない（null）**ためテンプレ既定の 1.0 を採用したが、ゲーム同業の実測は 0.11〜0.49 と大幅に低く、**Ke 10.47% は過大の可能性が高い**。同銘柄の最大の未解決事項。

## 4. シナリオ導出 — **§4-3 の機械適用は片側でしか正しくない。対称ルールに拡張した**

§4-3 は「Base の OPM は実績中央値へ収束」「Downside 1 は実績25%分位」とするが、パイロット4件のうち**3件で機械適用が破綻**した。

| 破綻の形 | 発生銘柄 | 採った対処 |
|---|---|---|
| **直近実績が中央値より上** → Base が根拠なきマージン悪化になる | 2802（直近12.08 vs 中央値10.25）、9022（41.38 vs 36.94） | Base の到達OPM = **直近実績と p75 の平均** |
| **直近実績が p25 より下** → Downside 1 が現状より良くなる | 4063（直近24.68 vs p25 27.90） | Downside 1 = **min(p25, 直近実績)** を起点に悪化 |
| **観測窓の最低値が直近実績そのもの** → Downside 2 のトラフが機能しない | 4063、7974 | §4-3 の代替アーム（**売上▲10〜15% + OPM半減**）を採用 |

**確立した対称ルール**（残り銘柄に一貫適用する）:
> Base 到達OPM = 直近実績 ≤ 実績中央値 なら **中央値**、直近実績 > 中央値なら **直近実績と p75 の平均**
> Downside 1 到達OPM = **min(実績p25, 直近実績)** を下回る水準
> Downside 2 = **実績トラフが直近実績と乖離していれば実績トラフ**、そうでなければ **売上▲10〜15%+OPM半減**

**Management シナリオは4件すべてで Base と同一**になった。EDINET XBRL・TDnet 短信のいずれからも会社業績予想を取得できていない（4件とも生成ログ Step 3 が `No guidance data found`）。**これは銘柄固有の問題ではなくパイプラインの構造的な取得失敗**であり、バッチ全体で Management シナリオが機能しないことを意味する。→ 最終レポートで報告。

## 5. Peer選定 — **時価総額バンド 0.3〜3倍は日本の大型株では成立しない**

4件すべてで **§5 の 0.3〜3倍バンドを緩和**せざるを得なかった。

| ticker | バンド内の同業数 | 対処 |
|---|---:|---|
| 4063 信越化学 | **1社**（10.5兆円に対し0.3倍以上の国内化学は 4901 のみ） | 業種同一性を優先しバンドを撤廃、5社採用 |
| 2802 味の素 | 3社 | 統計安定のため2社をバンド外から追加 |
| 9022 JR東海 | 3社 | 統計安定のため1社をバンド外から追加 |
| 7974 任天堂 | **2社** | 3社確保のため3社をバンド外から追加 |

**原因**: 本リストは各セクターの首位企業が中心で、同一業種内に同規模の比較対象が存在しない。バンドを守ると Peer が3社未満になり EV/EBITDA が `INVALID (n<3)` 化する。
**採用した運用**: **業種同一性・事業比較可能性を第一基準とし、時価総額バンドは第二基準**として3〜6社を確保。逸脱は全件 Adjustments Log と本サマリーに記録する。

**副作用**: 首位企業の Peer は必ず自社より低マージン・低倍率になるため、**Comps 由来の Exit 倍率が系統的に保守側へ振れる**（4063: 自社 10.35x に対し Peer中央値 9.22x、2802: 18.89x に対し 10.92x、7974: 22.34x に対し 13.17x）。SELL 寄りのバイアス要因。

## 6. exit_multiple の導出ルール — **一度作り直した**

当初「Peer中央値 × (1 + 0.5×マージン優位率)」という品質調整式を設計したが、**9022 で 16.3x を返して破綻**した（当社の実測 EV/EBITDA は 7.36x）。原因は **EV/EBITDA が既に資本集約度を織り込んでいる**ため、営業利益率による上方調整が資本集約型銘柄で逆方向に働くこと。

**恒久ルールとして「素の Peer中央値 EV/EBITDA」に確定**した。発明した係数を含まず、自社の株価・倍率を参照しないため市場価格への循環参照も生じない。型B の §4-4 上限（Peer中央値）とも自動的に整合する。4063 は当初 9.2x で生成済みだったため**再生成して統一**した。

## 7. capex ターミナル収束 — **§4-2 の既定は多くの銘柄で結論を左右する**

- 4件中3件で `capex_direct` の明示パスが必要だった（4063 / 2802 / 9022）。revenue_pct のままでは capex/D&A 比率がレンジ外になる。
- **9022 では感応度を実測**した。「リニア建設が Y5 以降も継続」前提に置き換えると Target 10,103 → **7,843円（−22%）**。判定は BUY のまま反転しない。**推定で済ませず実際にバリアントを生成したことで、当初の概算（約2,900円）が大きく外れていたことが判明した**。同種の重要判断は今後も実測する。

## 8. 品質ゲート — **4件すべて FAIL 0 / WARN 0**

- 唯一の FAIL は 2802 の初回（`Financial Statements!D16:F16 = #DIV/0!`）。原因は **EDINET が FY2022–FY2024 の営業利益を 0 で抽出**していたこと。リトライ1回で解消。
- **EDINET の抽出品質は銘柄によって大きく異なる**。9022 は 6/6 完璧、4063 は 4/4、7974 は Debt 0/6（無借金という事実で正常）、2802 は最新期欠落＋3期分の COGS/OP 破損。**バッチでは「生成ログの FS align 行と LTM 行を必ず読む」ことが必須工程**であることが確認できた。

## 9. 残り 75銘柄への適用方針（このパイロットで確定したこと）

1. 生成前に **EDINET XBRL の金融事業科目チェック**を行う（KDDI 型の見落とし防止）
2. beta は **max(0.6, min(1.75, 実測))**、null は 1.0＋要確認
3. シナリオは **§4 の対称ルール**（上記 4.）で導出
4. exit_multiple は **素の Peer中央値 EV/EBITDA**
5. Peer は **業種同一性優先・バンドは第二基準**で3〜6社
6. 生成ログの **FS align / LTM / guidance 行を必ず読み**、破損があれば `fundamentals_fy<YYYY>` と hist_* で補完（hist_years を上書きするときは全 hist_* 配列を同時に供給する）
7. 結論を左右する前提は **推定で済ませずバリアントを生成して実測**する

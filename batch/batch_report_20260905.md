## 5. スキーマ・テンプレートとの食い違い報告（§0・手順書§6-6）

### 5-1. beta のクランプ域 — **本プロンプト §4-1 と実装が矛盾する（重大）**

- **本プロンプト §4-1**: 「0.4未満は0.4、1.8超は1.8にクリップ」
- **実装（`templates/dcf_comps_template.py:1819`）**: beta を **[0.6, 1.75]** にクランプし、**範囲外は無言で 1.0 に置換**する

仕様どおり 0.4 を書くと **1.0 に置き換えられ、低ベータ銘柄の WACC が 2〜4pt 跳ね上がる**。これは §0 が禁じる「サイレントフォールバック」そのものである（生成ログにも `Beta 0.372 outside [0.6, 1.5] range - using fallback 1.0` と出る）。

**採った運用（追補1 §A で正式化）**: `beta = max(0.6, min(1.75, 実測))`。生成19件中 **15件**で実測が 0.6 を下回り、下限 0.60 を明示指定した（実測をそのまま使えたのは 4063 1.062 / 4183 0.78 / 4188 0.686 / 3407 0.645 の4件のみ、7974 は yfinance が null）。**0.60 は実測値ではなく「テンプレが受け付ける最小値」**であることを各 Adjustments Log に記録している。

> **要判断**: プロンプト §4-1 を実装に合わせて改訂するか、テンプレのクランプ域を [0.4, 1.8] に広げるか。日本の大型ディフェンシブ銘柄の実測 beta は 0.0〜0.4 に集中しており、現状のクランプは**それらすべてを 0.6 に張り付かせている**。

### 5-2. size_premium — 本プロンプトとテンプレ自動規則が食い違う

- **本プロンプト §4-1**: >3,000億円 → **1.0%**
- **テンプレ自動規則（同 1822–1832行）**: ≥1兆円 → **0.0%** / ≥1,000億円 → 1.5% / それ未満 → 3.0%

**本リスト90銘柄はすべて時価総額3,000億円超**のため、プロンプトのバンドは**例外なく 1.0%** を返す（5段階のバンドが機能していない）。テンプレ自動値との差は 1兆円超の銘柄で **+1.0pt の WACC 上乗せ**になる。明示指定でプロンプト側を採用したが、全銘柄の Target を系統的に押し下げている。

```python

def _val(data_dict, key, default=0):
    v = data_dict.get(key)
    return v if v is not None else default          # ← 欠損が 0 になる
```

`hist_revenue` / `hist_cogs` / `hist_operating_income` / … の**全系列**がこの `_val` を通る。EDINET パーサが古い
有報から `OperatingProfitLossIFRS` / `OperatingIncome` / `OperatingProfit` のいずれも見つけられなかった年は、
**None ではなく 0** が入る。その 0 が「営業利益YoY成長率 = (当年 − 前年) ÷ 前年」の分母になって `#DIV/0!` を出す。

**同じ 1 行が net_debt の誤り（§6-2）も説明する**: `net_debt = _val(base_data, "net_debt")`（169行）も
欠損時に 0 を返すため、2801 で `net_debt = 0`、2897 で `4,418` という誤った値が**警告なしで**通っていた。

**修正提案**: (a) `_val` の `default` を **`None`** にし、0 を意味のある値として扱う箇所だけ明示的に 0 を渡す、
(b) 成長率行に `IFERROR` / ゼロ除算ガードを入れる、(c) `net_debt` が欠損で 0 になった場合は警告を昇格させる、
(d) `--years 5` を指定しても hist_years が8〜9期に膨らむ挙動を見直す。
**いずれも影響範囲が広いため、追補1 §D に従いバッチ中は変更していない。**

**バッチでの回避策（確立済み）**: `hist_years` を直近4期に置換し、P/L 5系列（revenue / operating_income / net_income / cogs / sga）を yfinance から供給する。**`hist_ocf` / `hist_cash` / `hist_debt` / `hist_capex` / `hist_depreciation` は供給しない** — Step 4.6 の `align_hist_series_to_years()` が最終 hist_years に対し会計年度キーで再マッピングするため、EDINET を一次ソースのまま安全に使える。

## 7. 設計ルールの確定事項（残り59銘柄へ一貫適用）

パイロット自己評価（`batch/pilot_assessment.md`）で確立し、その後の5銘柄でも適用したルール:

1. **型判定**: 生成前に `batch/fin_business_screen.py` で EDINET XBRL の金融事業科目をチェック（KDDI 型の見落とし防止）
2. **beta**: `max(0.6, min(1.75, 実測))`。null は 1.0 ＋「推定・要確認」
3. **シナリオ（§4-3 の対称ルール）**:
   - Base 到達OPM = 直近実績 ≤ 実績中央値 なら **中央値**、直近実績 > 中央値なら **直近実績と p75 の平均**
   - **単調系列（4期連続同方向）の特則**: **(直近実績 + 中央値)/2** ← 2267 ヤクルトで確立
   - Upside 到達OPM = **max(実績p75, 直近実績 + 1.0pt)**
   - Downside 1 到達OPM = **min(実績p25, 直近実績)**（型B で直近がサイクル谷の場合は p25 を使い、谷は Downside 2 が担う）
   - Downside 2 = **実績トラフ**が直近実績と乖離していればそれ、そうでなければ **売上▲6〜15% + OPM半減**
4. **exit_multiple = 素の Peer中央値 EV/EBITDA**。**マージン品質調整式は棄却した**（EV/EBITDA は既に資本集約度を織り込むため、営業利益率による上方調整は資本集約型で逆方向に働く。9022 で実測 7.4x に対し調整式が 16.3x を返した）
5. **Peer 選定**: 業種同一性・事業比較可能性が第一基準、時価総額バンド 0.3〜3倍は第二基準。3〜6社を確保し、逸脱は全件記録
6. **EDINET 破損への対処**: hist_years を直近4期に置換 + P/L 5系列を供給。CF/BS 5系列は供給せず Step 4.6 の年度キー再マッピングに委ねる
7. **結論を左右する前提は推定で済ませず、バリアントを生成して実測する**（9022 で実施。当初の概算 約2,900円 に対し実測は 7,843円 で、概算は大きく外れていた）
8. **EDINET 破損は発生を待たず予防的に補完する**（第2セッション後半で確立）。`hist_years` を直近4期に置換し
   P/L 5系列（revenue / operating_income / net_income / cogs / sga）を供給する。**CF/BS 5系列は供給せず
   Step 4.6 の年度キー再マッピングに委ねる**。3407 / 4091 / 4151 / 4502 / 4503 の5銘柄すべてが初回合格した
9. **生成後に `batch/check_core_ebitda.py` を必ず実行する**（§6-7）。validate FAIL 0 でも Comps 参考値が
   消失・負値化していることがある
10. **追補1 §D に従い、validate FAIL 0 でも net_debt 構成と WACC inputs の数値照合を省略しない**（§6-8）
11. **製薬・素材など「売上 − COGS − SGA ≠ 営業利益」の銘柄**（研究開発費・無形資産償却が yfinance の SG&A に
   含まれない）は、**COGS% を実績水準に固定し SGA% = 100% − COGS% − 目標OPM で逆算**する。
   モデルの SGA 行が「販管費 + 研究開発費 + 無形資産償却」の合計になることを summary に明記する

## 10. 追補2 で確定した運用（第3セッション〜）

### 10-1. `_val` 欠損=0 問題 — 予防的補完を全銘柄に必須化（追補2 §F-2）

第2セッションまでは「FAIL が出た銘柄に対症」だったが、**追補2 §F-2 により残り全銘柄に生成前適用**する。
`batch/preemptive_block.py`（銘柄コードを含まない汎用スクリプト）が、キャッシュから

- `hist_years`（P/L 4項目がすべて揃う直近4期）
- `hist_revenue` / `hist_operating_income` / `hist_net_income` / `hist_cogs` / `hist_sga`（= 売上 − COGS − 営業利益 で逆算）
- `base_year_revenue` / `base_year_cogs` / `base_year_ar` / `base_year_inv` / `base_year_ap` / `book_value`
- **`core_ebitda`**（= 直近営業利益 + 直近CF計算書D&A。追補2 §G 対応）

を機械生成する。**CF/BS 5系列（ocf / cash / debt / capex / depreciation）は供給しない** — Step 4.6 の
`align_hist_series_to_years()` が最終 `hist_years` に会計年度キーで再マッピングするため、EDINET を一次ソースの
まま安全に使える。

**実績**: 予防適用した銘柄は第2セッション後半5件（3407 / 4091 / 4151 / 4502 / 4503）が **5/5 初回合格**。

### 10-2. バッチ完了後の「再生成で統一」予定（追補2 §F-3）

パイプライン修正（`_val` の `default=None` 化ほか §6-1 / §6-7 / §6-8 の提案）を適用したのち、
**本バッチで生成した全銘柄を修正済みパイプラインで再生成して統一する**。

根拠は手順書§5-4 の原則「恒久修正後テンプレでの**再生成**が手修正の再適用より速く、validate が効く」。
overrides / comps CSV / adjustments 設定はすべて `data/` 配下に残るため、**再生成コストは1銘柄あたり数分**で済む。
現時点で回避策（overrides 側の予防的補完・`core_ebitda` 明示指定・`net_debt` 明示指定）を入れている銘柄は、
修正後は回避策を外して EDINET 一次ソースに戻せる可能性がある。**その差分確認も再生成時に行う。**

### 10-4. ハード停止ルールの再武装（追補2 §I）

## 13. 第4セッションの構造的発見 — 高倍率セクターで DCF と市場倍率が両立しない

part1（電機・機械）に入って、**これまでの銘柄群では顕在化しなかった方法論上の限界**が出た。

### 13-1. 半導体製造装置3銘柄で PGM と Exit が5〜6.7倍乖離した

| ticker | PGM | Exit | 乖離 | Target | WARN 11 の乖離倍率 |
|---|---:|---:|---:|---:|---:|
| 6146 ディスコ | 16,852 | 60,612 | **3.6倍** | 38,732 | 5.57倍 |
| 6857 アドバンテスト | 4,288 | 13,572 | **3.2倍** | 8,930 | 5.03倍 |
| 8035 東京エレクトロン | 9,967 | 42,869 | **4.3倍** | 26,418 | **6.67倍（本バッチ最大）** |

**Target はこの2つの中点にすぎず、点推定として読んではいけない。**

### 13-2. 原因は倍率の選び方ではなく「永久成長率 1.0% 固定」という前提

- 本バッチのグローバル前提（**g = 1.0%**、ERP 6.5%、size premium 1.0%）で PGM を計算すると、
  逆算される Exit 倍率は **5〜7倍**にしかならない（WACC 10.5〜12.6% に対し g=1.0% なので分母が約10%）。
- 一方、半導体製造装置セクターの Peer 中央値 EV/EBITDA は **31〜39倍**。
- **市場が30倍超を払うのは、この事業の長期成長が 1% をはるかに超えると見ているから**である。
  g=1.0% を置く限り、DCF は構造的に市場倍率と両立しない。
- §4-4 の「ピーク利益×高Exit倍率の二重計上禁止」は**形式的には満たしている**

### 15-3. 構造的所見 — 乖離の真因は「谷」だけではない（資本集約度）

### 15-6. パイプラインの新規発見 — `generate_dcf.py` は `--force` なしで**黙って再生成をスキップし exit 0 を返す**

3. **done 39銘柄すべてに対して stale 監査を実施**（overrides の mtime > model の mtime を検出）。

`--force` 未指定で既存ファイルがある場合は**非ゼロ終了して validate に進まない**のが正しい。

### 17-3. §X が塞いだ穴 — 6981 が導入の契機

6981 の乖離 **4.55倍** は、追補5 §U で個別裁定した 6752（4.41倍）・6506（3.55倍）より**大きい**。
にもかかわらず、直近OPM 15.39% が窓p25 14.83% を**わずか 0.56pt** 上回るというだけで §U の第1条件を外れ、
§Q も仮定Exit 17.20倍 ≤ 25倍で非該当となり、**追補5 が禁止したはずの中点平均がそのまま Target になっていた**。

**旧構造の問題**: §Q は「倍率の高さ」、§U は「分母の位置」で切っていたが、実際に困っているのは**乖離の大きさ**そのもの。
**§X は乖離を単独トリガーに変え、§Q / §U を「どちらの脚を落とすか」の判断材料に格下げした。**

**バンドテストの設計意図（記録）**: 市場倍率を無条件のアンカーにすると、スクリーナーは市場の複写に堕して存在意義を失う。
バンドテストは **実際に取引されているレンジの外に出た脚だけを取り除く**という位置づけであり、
「市場が正しい」とは言っていない。両脚がバンド内なら平均を維持し、両脚がバンド外ならバッチでは判断せずキューへ送る
（本バッチでは該当なし）。

## 21. 追補8 の適用（第8セッション）— rework wave と3つの新フラグ

### 21-1. **⚠ §AE-2 の定義で再算定すると、§AE-3 が示した影響と符号が逆になる（報告事項）**

追補8 §AE-3 は rework の影響を「**−0.06〜−1.14pt**」（Target が下がる方向）としていた。
これは第7セッションのレポート §19 で当方が提示した表の数値だが、**その表は単調増加にも
(直近 + 中央値)/2 を当てて算出していた**。

一方 **§AE-2 は単調増加のトレンド整合を「直近水準の維持」と定義**している。

**§AE-2（定義）に従った**。理由は §Y 自身の論理である:

> (直近 + 中央値)/2 は**平均回帰そのもの**である。§Y は「トレンドに平均回帰を当てるのは統計的な誤り」
> という理由で成立している以上、単調増加にそれを適用すれば §Y は自己矛盾する。
> §AE-2 の「直近水準の維持（さらなる上積みの外挿はしない）」は、
> **平均回帰でもトレンド外挿でもない中間**であり、§Y の論理と整合する唯一の選択である。

§AE-3 の数値は当方が提示した旧定義の表を引き写したものと理解し、**定義（§AE-2）を優先した**。

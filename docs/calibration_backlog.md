# 校正バックログ（実データで決める値・既知の制限）

統合引継ぎ書 v1.1 §8 の「要キャリブレーションのパラメータ」と、実装中に判明した
既知の制限を1か所に集める。**ここに書かれた値はすべて仮置きであり、実データの
バックテストで校正するまで運用判断の根拠にしてはいけない。**

更新: 2026-08-31

## 1. 既知の制限（設計上の穴。パラメータ調整では解決しない）

### 1-1. S6 / 本体S2 の在庫両義判定は実データで「シグナルなし」に退行する

**状態**: 承認済みの既知の制限（2026-08-31）。現行実装の変更は不要。

原価の数量／価格分解（`cogs_quantity` / `cogs_price`）は、**本体にも実XBRLにも
該当科目が存在しない**ことを確認済み。別枠 `mock/generate_mock_financials.py` は
生成時に人工的に注入しているだけで、実データには対応物が無い。

影響:

| 指標 | 実データでの挙動 |
|---|---|
| 別枠 S6（在庫両義スコア） | 「原価の数量/価格分解データなし → 中立」で score=0 / available=False |
| 本体 S2（在庫の価格/数量分解） | `cogs` は取れるが「価格プロキシ」としての妥当性が未検証。分解の体を成さない |

投影層 `adapter.get_pl_series()` は `cogs_quantity` / `cogs_price` に **`None` を
明示的に返す**（0 を返さない）。「データが無い」と「値がゼロ」を混同しないため。
この実装は正しいので変更しない。

**再設計の宿題**: 原価率変動を代理変数で分解できないか検討する。候補として
（a）棚卸資産の内訳（商品/仕掛/原材料）の構成比変化、（b）為替感応度の高い
セクターでの為替×原価率の回帰、（c）セグメント別の売上原価率の分散。
いずれも本体 `account_mapping.yaml` に既にある項目で試せる。
**着手時期は未定。S1/S3/S4/S5 の実データ検証を優先する。**

### 1-1b. 単一レジームへの過剰適合リスク

**パラメータ校正は 2023〜2024年の単一レジームのデータに基づく。** バックテスト窓が
その期間に確定するのは、四半期単独値を作れるのが EDINET 四半期報告書のある
FY2023〜FY2024 に限られるため（制度は 2024-04-01 以後開始の四半期から廃止）。

同一の相場環境・金利環境・為替環境のデータだけで閾値を決めると、環境が変わった
瞬間に効かなくなる。**TDnet の前向き蓄積が進んだ時点で、第2レジーム（2026年以降）
での再検証を必ず行うこと。** 5四半期深度への到達は約15ヶ月後（2027年11月頃）。

再検証前に運用へ乗せる場合は、校正値を「暫定」と明示し、ポジションサイズを
抑えること。第2レジームで再現しなかった指標は落とす。

### 1-2. 日次株価が2年分ない

**2026-08-31 実測**: 無料プランの提供範囲は API が明示している ——
`Your subscription covers the following dates: 2024-06-08 ~ 2026-06-08`
（2年ローリング + 12週遅延）。2024-06-07 以前は HTTP 400 で取得できない。

これは財務データ側の窓と**噛み合わない**。EDINET 四半期報告書から作れる
連続四半期は FY2023〜FY2024（2022-04〜2024-03）で、**株価が1日も重ならない**。

| プラン | 月額 | 遡及 | TOPIX |
|---|---:|---|---|
| Free | ¥0 | 2年（直近12週を除く） | **含まれない** |
| Light | ¥1,650 | 5年 | 含まれる |
| Standard | ¥3,300 | 10年 | 含まれる |
| Premium | ¥16,500 | 20年 | 含まれる |

2022年以降の株価と TOPIX を揃えるには **Light 以上が必要**。

### 1-3. PTS 出来高のデータソースが無い

**状態**: 「当面は取得せず、翌日寄り指値固定」の fallback を承認済み（2026-08-31）。

J-Quants V2 は東証の公式配信で、取引所外取引である PTS の出来高はエンドポイントに
存在しない。無料APIも把握していない。`decide_exit()` は `pts_ratio=None` を受けると
自動的に「翌日寄り指値（PTSデータなし）」を返すため、コード変更は不要。

**再判断の条件**: 実データバックテスト後に「PTS約定できていた場合の損益改善幅」を
定量化できた時点で、有料データ調達の是非を判断する。それまで保留。

### 1-4. 前年同期の取り方が位置ベース（別枠）

別枠 `scorers_s1_s4.py` の S1/S2、`scorers_s5_s8.py` の S6 が `pl[-5]` / `cl[-5]` で
前年同期を取る。`is_valid=0` で期が欠けると前年同期でなくなる。v1.1 でも意図的に
未修正。本体側で使う場合は `(quarter_type, fiscal_year - 1)` のキー突合に変える
（v1.1 §4-1）。**本体 `signal_defs.Series.prev_y()` は既にキー突合になっている。**

### 1-5. 未接続の item_key

`config/earnings_screener_mapping.yaml` 参照。verified 以外は投影層が空を返す。

| item_key | 状態 | 解消に必要なこと |
|---|---|---|
| `deposits_received` | unverified | 「預り金」と本体 `advances_received`（前受金）の意味が一致するか実データ突合 |

| `rev_point_in_time` | missing | 一時点移転の収益。S10 に必須 |
| `diluted_shares` | missing | 潜在株式調整後の株式数。S11 に必須 |

4. S6 / 本体S2 の再設計（1-1）に着手するか判断する

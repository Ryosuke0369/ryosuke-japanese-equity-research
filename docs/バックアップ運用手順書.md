## 0. なぜバックアップが必須構成要素なのか

`DATA_ROOT` は **再生成できない一次資料** である。

| データ | 失うと何が起きるか |
|---|---|
| `raw/tdnet/` | TDnet の保持期間は約1ヶ月。過ぎた日の短信は**二度と取得できない** |
| `raw/edinet/` | 生 zip。API から引き直せるが全期間の再取得は現実的でない |
| `screener.db` の `prices` | J-Quants Light のカバレッジは **5年ローリング**。窓から落ちた日付は再取得不能 |
| `screener.db` のパース結果 | 上記 raw の派生物。raw を失えば再生成もできない |

つまり **ローカルの `DATA_ROOT` が唯一の正本**であり、バックアップは
「あれば良いもの」ではない。

## 1. このマシンの構成上の限界（必ず読むこと）

**このPCは物理ディスク1台構成である**（Disk 0 / 952.4GB / C: 単一パーティション）。

そのため日次バックアップは `-AllowSameDisk` を付けて同一ディスク上に取っている。
これは `backup_data.ps1` が既定で拒否する構成であり、意図的に押し切っている。

> **⚠ 警告: 同一ディスク上のコピーはディスク故障に対する保険にならない。**
> 日次バックアップが守れるのは「誤削除・誤上書き・DB破損」までである。
> ドライブが物理的に死ねば、本番もバックアップも同時に失われる。

唯一のオフディスク保護は、退避先が OneDrive 配下（`%USERPROFILE%\OneDrive\backup\screener`）
であり、クラウド側にコピーが上がることだけである。ただし日次分は
`-DbAndLogsOnly` なので、**`raw/` 8.5GB はクラウドにも上がっていない**。

**したがって §3 の外付けディスクへのフルバックアップを、別途必ず取ること。**
これを取るまで `raw/` は単一ディスク上に1部しか存在しない。

## 2. 日次バックアップ（登録済み・自動）

タスク名 `ScreenerDataBackup` / 毎日 03:30 / ログオン中のみ実行。

```
ScreenerDataBackup  毎日 03:30
  powershell.exe -NoProfile -ExecutionPolicy Bypass
    -File "C:\dev\ryosuke-japanese-equity-research\screener\backup_data.ps1"
    -Destination "%USERPROFILE%\OneDrive\backup\screener"
    -PythonExe "C:\dev\ryosuke-japanese-equity-research\.venv\Scripts\python.exe"
    -DbAndLogsOnly -AllowSameDisk
```

- 対象は **DB と `logs/` のみ**（約1.4GB）。`raw/` は同期に流さない
- `current/` = 差分ミラー、`snapshots/YYYYMMDD` = 7日間隔のフルコピーを2世代
- DB は robocopy ではなく **SQLite の `backup` API** で一貫コピーを作る
  （稼働中の DB を robocopy で取ると WAL と食い違った壊れたファイルが取れる）
- 03:30 は日次収集（19:00 / 23:15）と重ならない時間帯

再登録・削除:

```powershell
$repo = 'C:\dev\ryosuke-japanese-equity-research'
$env:PATH = "$repo\.venv\Scripts;$env:PATH"   # ← 必須。後述
powershell -ExecutionPolicy Bypass -File $repo\screener\install_backup_task.ps1 `
  -Destination "$env:USERPROFILE\OneDrive\backup\screener" -DbAndLogsOnly -AllowSameDisk

powershell -ExecutionPolicy Bypass -File $repo\screener\install_backup_task.ps1 -Remove
```

> **なぜ `$env:PATH` に venv を通してから登録するのか**
> `install_backup_task.ps1` は登録時点の `python` を解決して `-PythonExe` として
> action に焼き込む。venv を通さずに登録すると、依存パッケージの入っていない
> システム python が焼き込まれ、`import screener.common` が `requests` で落ち、
> **ログを1行も残さずに毎晩失敗する**（2026-09-10 に実際に踏んだ）。

## 3. 外付けディスクへのフルバックアップ（手動・必ず一度は取る）

外付けディスクを接続したら、**この1コマンドで完了する**。
`-DbAndLogsOnly` を付けない = `raw/` を含む `DATA_ROOT` 全体（約10.3GB）が対象。

```powershell
# 1. 外付けのドライブレターを確認する
Get-Volume | Where-Object DriveType -eq 'Removable' |
  Select-Object DriveLetter, FileSystemLabel,
    @{n='FreeGB';e={[math]::Round($_.SizeRemaining/1GB,1)}}

# 2. フルバックアップを実行する（E: は実際のドライブレターに読み替える）
$repo = 'C:\dev\ryosuke-japanese-equity-research'
$env:PATH = "$repo\.venv\Scripts;$env:PATH"
powershell -ExecutionPolicy Bypass -File $repo\screener\backup_data.ps1 `
  -Destination 'E:\screener_backup' -KeepSnapshots 2
```

- **`-AllowSameDisk` を付けない**。外付けは別ディスクなので不要であり、
  付けないことが「うっかり内蔵ディスクを指した」場合の安全装置になる
  （別ディスクでなければスクリプトが自分で止まる）
- **`-DbAndLogsOnly` を付けない**。`raw/` を含めるのがこの手順の目的
- 必要な空き容量は約 **23GB**（`DATA_ROOT` 10.3GB × 2.2 = ミラー + スナップショット1世代）。
  スクリプトが事前に空き容量を確認し、足りなければ実行前に止まる
- 初回は10GB超のコピーになるので時間がかかる。2回目以降は robocopy の差分ミラーなので速い

事前に中身だけ確認したい場合:

```powershell
powershell -ExecutionPolicy Bypass -File $repo\screener\backup_data.ps1 `
  -Destination 'E:\screener_backup' -WhatIf
```

### 推奨頻度

`raw/` は追記のみで書き換わらないため、**月1回程度**で十分。
ただし **TDnet の保持が約1ヶ月**なので、2ヶ月以上空けると
「内蔵ディスクが死に、かつ外付けにも無い」短信が発生しうる。

## 4. 復元手順

```powershell
# DB だけ壊れた場合（raw は無事）
Stop-ScheduledTask -TaskName ScreenerTdnetArchiver -ErrorAction SilentlyContinue
Copy-Item "$env:USERPROFILE\OneDrive\backup\screener\current\screener.db" `
          'C:\screener_data\screener.db' -Force
# WAL/SHM は捨てる。復元した .db と食い違うため
Remove-Item 'C:\screener_data\screener.db-wal','C:\screener_data\screener.db-shm' `
            -Force -ErrorAction SilentlyContinue

# 復元後は必ず整合性を確認する
$repo = 'C:\dev\ryosuke-japanese-equity-research'
& $repo\.venv\Scripts\python.exe -c "import sqlite3; print(sqlite3.connect('C:/screener_data/screener.db').execute('pragma integrity_check').fetchone()[0])"
```

`raw/` ごと失った場合は、外付けの `E:\screener_backup\current\` から
`C:\screener_data\` へ robocopy で戻す。

## 1. 3テンプレートの役割と使い分け

| テンプレート | 答える問い | いつ作るか |
|---|---|---|
| **DCF/Comps**(前提) | この会社はいくらの価値か | 常に最初。他の全テンプレの入力になる |
| **market_analysis** | **市場は今いくらの成長を織り込んでいるか**、自分の見方とのギャップはどちら向きか | カバレッジ銘柄で売買判断を出すとき。DCF完成後の標準の次工程 |
| **SOTP** | 複合企業の部分の和はいくらか、市場はどの事業にいくら払っているか | 型E(持株会社)・多セグメント複合企業(IHI型)・セグメント間で適正倍率が大きく異なる銘柄 |
| **narrative_stage** | この銘柄の「物語」は市場にどこまで浸透したか(乗るのは早いか遅いか) | market_analysisのオプションブロック。テーマ性のある銘柄で有効 |

## 2. 共通の前提条件(全テンプレ共通・作業前に必ず確認)

### 2-1. 入力DCFファイルの再計算(最重要)

market_analysis と SOTP のクロスチェックは、DCF Excelを `data_only=True` で読む。**一度もExcel(またはLibreOffice)で再計算・保存されていないファイルは数式のキャッシュ値が存在せず None が返る**。

- market_analysis は WACC等の必須値が None だと**意図的にエラー停止**する(エラーメッセージに従い再計算してから再実行)
- SOTP のクロスチェックは None だと "N/A — Run DCF first" 表示に落ちる(エラーにはならないが表が空になる)

手順: DCFのFINALをExcelで開く → F9(全再計算)→ 上書き保存。またはリポジトリの `scripts/recalc_excel_com.py`(Windows/Excel COM)を使う。

### 2-2. DCFのアクティブシナリオを Base にしておく

market_analysis の抽出は「Baseシナリオの成長・OPM」はシナリオ行列から直接読むが、**D&A / Capex / ΔNWC はアクティブシナリオの行から読む**(仕様上の既知の制約)。アクティブシナリオがBase以外のまま保存されていると、生成後の自動検証 `alpha=1.0 vs Base PGM` が乖離警告を出す。**DCF側でドロップダウンをBaseに戻し、再計算・保存してから**使うこと。恒久修正後のDCFはシナリオ切替が全銘柄で正しく動く(D27はMATCH式)。

### 2-3. 入力DCFの世代確認

- **恒久修正後に生成されたDCF**: そのまま使える。Comps統計は自社除外済みで、market_analysis 側のpeer-only統計と完全一致する(3687で検証済み)
- **旧テンプレ生成のDCF**(2026-07-30以前のFINAL): 使えるが、逆算Compsで `[Comps] NOTE: … Regenerate the DCF with the current template.` が出て、`_verify_comps_median_matches_c27` が警告する(シート統計セルが自社込みのため)。**market_analysis 側は自動的にpeer行から自社除外統計を再計算して使う**ので出力自体は正しい — 警告は「DCFを再生成すれば消える」という意味。急ぎでなければDCFは次に触るタイミングで再生成すればよい

## 3. 手順A: market_analysis(市場認識分析)

### 3-1. ユーザーが用意する入力

Claudeはまず以下をユーザーに確認する(すべてconfigに入る):

| 項目 | configキー | 備考 |
|---|---|---|
| 現在株価 | `current_price` | 必須。時点を明記 |
| 取得単価 | `entry_price` | 保有中なら。なければ省略 |
| 3ヶ月前・1ヶ月前株価 | `price_3m_ago` / `price_1m_ago` | スコアカードFactor 2(モメンタム)用 |
| 直近高値・安値 | `price_high` / `price_low` | 同上+価格ポイント |
| 信用買残・売残(千株) | `margin_buy` / `margin_sell` | スコアカードFactor 3用 |
| 過去6ヶ月の売残ピーク(千株) | `margin_sell_peak_6m` | 同上 |
| 会社予想の営業利益成長率・売上成長率 | `company_op_growth` / `company_rev_growth` | Factor 4(予想ギャップ)用。小数(0.113=+11.3%) |
| 会社予想売上(任意) | `forward_revenue` | 逆算Compsのフォワード倍率分母 |
| 利確/損切り価格(任意) | `price_targets` dict | 逆算CompsのBlock D。**実際の取引水準はリポジトリにコミットしない** |
| ナラティブ6軸(任意) | `narrative` | §4の採点手順で決める |

**未入力の扱い**: 信用残・モメンタムが取れない場合は**空欄のままでよい**(該当Factorはニュートラル0点として扱われる)。ダミー値を埋める必要はない。ただし空欄のFactorの判定文は読まないこと。

**カスタム price_points を渡す場合**: 先頭要素は必ず `Current Price` にする(Block 4/5がその行のαを参照する。順序違反は生成時に警告が出る)。

### 3-2. segment_layout の決定

- DCFに `Segment Analysis` シートが**ある**銘柄: 各セグメントの `dcf_fy26_cell`(最終実績年の売上セル)、`dcf_growth_base_row` / `dcf_opm_base_row`(Base行の行番号)を **DCFファイルを実際に開いて特定**し、segment_layout に書く。2359の実例: rows 34/41、48/55、62/69
- **ない**銘柄(単一事業): segment_layout を省略。テンプレートが Scenario Input Matrix からBase成長・OPMを、Financial Statements から連結実績を自動で読む(4192の実例)

DCF Model・Comps の主要値の読取はラベル探索ベース(恒久修正M3)なので、DCF側の軽微な行ズレには追随する。ラベルで見つからない項目は固定番地フォールバックに落ち**警告が出る** — 警告が出たら該当ラベルがDCF側で変わっていないか確認する。

### 3-3. 実行

configとdriverスニペットを作り、ClaudeCode(または直接python)で実行:

```python
from market_analysis_template import generate_market_analysis_excel
generate_market_analysis_excel(config, "models/<ticker>_market_analysis_<日付>.xlsx",
                               dcf_excel_path="models/<ticker>_DCF_Model_<日付>_FINAL.xlsx")
```

出力先は `models/`(検証が済むまで `reports/` に置かない)。生成後に必ず:

```bash
python scripts/validate_output.py models/<ticker>_market_analysis_<日付>.xlsx
```

validate_output.py はシート名で種別を自動判別し、market_analysis には項目14-16・20(IFERROR補間 / 分布への自社非混入 / implied price昇順 / 社数表記整合)を適用する。**FAIL 0件が最終化の条件**。

### 3-4. 生成直後の自動検証(コンソール出力を必ず読む)

1. **`alpha=1.0 vs DCF Base PGM`**: 乖離>5%で警告。原因はほぼ「アクティブシナリオ≠Base」「stub不整合」。§2-2に戻る
2. **`EV/Sales-median price vs DCF Comps C27`**: 乖離>1円で警告。恒久修正後DCFなら一致するはず。**旧テンプレDCFが入力なら警告は既知**(§2-3。peer-only vs 自社込みの差であり、market_analysis側の出力は正しい)
3. **`[Comps] NOTE: Regenerate the DCF …`**: 旧テンプレDCF検出の通知。DCF再生成の要否をユーザーに確認
4. **Stub Fraction警告**: 期央評価なのに0なら要確認、期初評価なら0で正
5. **implied price 非昇順警告**: Base成長が負の銘柄で出る。この場合α補間の解釈が逆転しているので、Block 3の数値は使わず個別に解釈する

### 3-5. シートの読み方(検証を兼ねる)

- **Implied Growth Analysis**: Block 3の Current Price 行の implied α が核。α=1.0はBase全織込み、0は成長ゼロ織込み、負は縮小織込み。価格がαグリッド(−0.5〜1.5)の外でも外挿で値が出る(グリッド外である旨は解釈時に意識する)。Block 5 の「My View alpha」(黄色セル)に自分のαを入れて判定を出す。赤字銘柄はNOPATフロア(MAX(0,·))により低αレンジのFCF曲線が平坦化する仕様(How to use に注記あり)
- **Implied Multiple Analysis(逆算Comps)**: 現在株価のimplied EV/Salesがpeer分布(自社除外・peer数は実数表示)のどこか(zスコア)。DCFと独立した第2の物差し
- **Market Scorecard**: 4要素加重(織込みα 40% / モメンタム 25% / 信用残 20% / 予想ギャップ 15%)。Block 4のシナリオ別αは実DCFシナリオではなく**αプロキシ**(列見出しに明記)
- **Narrative Stage**: §4参照。スコアセルは出力色 — **Excel上で編集しても判定は動かない**(シート内に注記あり)。変更はconfig修正→再生成で行う

## 4. 手順B: ナラティブ6軸の採点(narrative config の作り方)

### 4-1. 軸の役割(確定仕様 2026-05-22)

| 軸 | 問い | 役割 |
|---|---|---|
| 軸1 ラベル現状 | 火種はあるか(銘柄の「呼び名」の書き換えは進んでいるか) | **Stageを動かさない**。軸3との差分がheadroomシグナルになる |
| 軸2A 触媒ポテンシャル | 燃料はあるか(触媒の源泉が存在するか) | Stage 0判定に関与 |
| 軸2B 触媒実現度 | 発火したか(触媒が市場に着弾済みか) | Stageの精緻化 |
| 軸3 拡散進行度 | 火はどこまで広がったか(個人→メディア→セルサイド→機関) | **Stageの主ゲート** |
| 軸4 業績寄与 | 物語は数字になるか | 0なら**Stage上限2**(キャップは下げる方向のみ。適用時は元のStageが `stage_pre_cap` として結果とシートに残る) |
| 軸5 物語持続性 | 物語は長持ちするか | 参考情報 |

補足: `軸1=0 かつ 軸2A=0` の Stage 0 判定は reach ゲートより**意図的に優先**される(docstringに明記済み)。

### 4-2. 採点基準(0 / 1 / 2)と参照ケース

- 軸3(ゲート): 0=誰も気づいていない / 1=個人投資家の一部 / 2=セルサイド・機関まで到達
- 軸2B: 0=触媒未発火 / 1=部分発火・続報待ち / 2=強い触媒が発火済み
- 迷ったら次の4基準ケースに照らす(`docs/narrative_stage.md` と `test_narrative_stage.py` が正):

| ケース | 軸1/2A/2B/3/4/5 | Stage | Headroom | 教訓 |
|---|---|---|---|---|
| コア 2359(2026-05) | 1/2/1/1/1/2 | **1** | BALANCED | 発火待ちの萌芽期の標準形 |
| 電業社 6365(2026-05) | 2/2/1/1/0/1 | **1** | HEADROOM | **軸1=2でもStageは上がらない**(ラベル定着≠到達)。軸4=0でもStage1にキャップは効かない(キャップは下げるだけ) |
| IHI 7013(2026-05) | 1/2/2/2/2/2 | **3** | SHALLOW | 到達がラベル書換に先行=逆行リスクの形 |
| フジクラ 5803(2023-01遡及) | 1/2/1/1/2/2 | **1** | BALANCED | 後のテンバガーのStage1時点の姿 |

### 4-3. 補助指標

- 業績インパクト: `TAM(億円) × 想定シェア% × セグメントOPM%` ÷ 現状営業利益 = 何倍化余地か。TAM/シェア/OPM/現状営利の4つをconfigに入れる(楽観ケースで良い — Stageと独立の「物語が数字になったときの上限」測定)
- `fundamental_verdict`: Block 2-4(スコアカード)の判定を BUY/HOLD/CAUTION で入れると、Stage×ファンダの最終Verdictマトリクスが出る(BUY×Stage0-1=STRONG_BUY 〜 CAUTION×Stage3-4=EXIT)

### 4-4. 採点の禁止事項

- 軸1が高いことを理由にStageを上げて解釈しない(電業社の教訓)
- 総合点(Total)でStageを決めない — Totalは監査用、Stageはグリッド判定
- 遡及採点(フジクラ型)をするときは**当時知り得た情報のみ**で採点する

## 5. 手順C: SOTP

### 5-1. 適用判断

型E(持株会社)または多セグメント複合企業で、(a) セグメント別の適正倍率が大きく異なる、(b) 上場子会社持分が時価総額の無視できない割合、(c) 連結DCFのExit法とセグメント積上げの乖離を見たい、のいずれかに該当するとき。

**着手前に必ず**: 上場子会社・持分法会社の**上場状態を最新確認**する(8267で上場廃止3社をSOTP候補に入れた事故。2025年はイオンモール/イオンディライト/ウエルシアが消えた)。

### 5-2. 入力データの構築(sotp dict / overrides)

| ブロック | 内容 | 注意 |
|---|---|---|
| `segments[]` | key / label / label_jp / fiscal_years / revenue[] / op[] / `da_allocation_pct` / `selected_multiple` / `multiple_source` / peers[] | 評価には**fiscal_yearsの最終年**が使われる(通常は予想年)。revenue/opは¥M |
| `peers[]`(セグメント毎) | name / ticker / ev_ebitda / opm / market_cap_usd_b / note / `excluded` フラグ | 除外Peerは `excluded: true` で**行は残しmedianから外す**(除外理由をnoteに)。medianは含めた社のみで自動計算される |
| `consolidated` | `da_total`(連結D&A) / `net_debt` / `minority_interest` / **`shares_outstanding`(千株!)** / equity_method_op / equity_method_multiple | **株数は千株単位**。DCF(株単位)と桁が違う。株単位で渡すと単位ガードがエラー停止する(閾値1e8千株。例: IHIは 151,364 が正、151,364,000 はエラー) |
| `conglomerate_discount` | base / sensitivity_range | ディスカウントの根拠をthesisに書く。base入力セルはSensitivity Table 2にも数式で伝播する |
| `sensitivity` | **`primary_segment_key`(必須。未指定はエラー停止)** / primary_multiples / table2(row/col segment+multiples) | Table1=主力セグメント倍率×ディスカウント、Table2=他2セグメントのクロス |
| `stock_split_ratio` | 分割予定があれば | post-split表示になる |
| `da_allocation_pct` | 全セグメント合計=100%必須(シート内Checkセルで検証される) | 配賦根拠は次項のキーで供給する |
| `da_allocation_intro` / `da_allocation_notes` | Sheet 6(D&A Allocation)の説明文と注記リスト | **銘柄別の按分根拠はここに書く**(overrides経由。7013_overrides.json が実例)。未指定なら汎用文(「セグメント別D&Aは非開示のため固定資産集約度で配賦」)のみが出る |

**D&A配賦の設計指針**: セグメント別D&Aが非開示の会社が対象になるため、配賦%は有形固定資産のセグメント内訳(有報の設備状況)から推定する。推定であることと根拠を必ず `da_allocation_notes` に残す。

### 5-3. 倍率選定(selected_multiple)

- 各セグメントのPeer medianを起点に、規模・成長率・OPM差で調整。medianからズラした場合は `multiple_source` に理由を書く
- **EV/EBITDA基準**なのでPeerのEBITDAはDCF側comps同様「営業利益+D&A」で統一。D&A不明のPeerは入れない
- 持分法投資は `equity_method_op ×倍率`(既定10x)の簡便法。重要なら個別時価に置き換える

### 5-4. 実行と検証

```python
from sotp_template import generate_sotp_excel
generate_sotp_excel(sotp, "models/<ticker>_SOTP_<日付>.xlsx",
                    dcf_excel_path="models/<ticker>_DCF_Model_<日付>_FINAL.xlsx")
```

生成後チェック:
1. 再計算(`recalc.py`)して数式エラー0件
2. `python scripts/validate_output.py models/<ticker>_SOTP_<日付>.xlsx` — SOTP用の項目17-19(D&A按分Check=OK / CoverのSOTP行が数式 / Fair Valueの桁)が適用される。**FAIL 0件が最終化の条件**
3. Cover のクロスチェック表: SOTP vs DCF PGM/Exit/Comps の乖離を確認し、**乖離の解釈を書く**(どのセグメントに市場が過大/過小に払っているか — 8267の「完全子会社群に1,065円 vs Exit法298円」型の分析)。読取はExec Summaryのラベル探索ベースで、DCF側のラベル文字列がそのまま手法名として表示される — 表示された手法名と値をDCF側と一度目視照合する
4. クロスチェック値は生成時スナップショット(表下に as-of 注記あり)。**DCFを更新したらSOTPも再生成する**

## 7. openpyxlで手修正するときの罠(重要度順)

1. **ラベル文字列を `=` で始めるとファイル自体が破損し得る**。`= Equity Value (¥M) × …` のような注記を書いた実例で、Excelがファイルを開けなくなりrecalcがCOMエラーで落ちた。#VALUE!で済む場合と、**ブック全体が開けなくなる場合**がある。ラベルは必ず `Fair Value = …` のように非 `=` 始まりにする
2. セル一括クリアのループは**参照されているセルを巻き込まない**(8267で株数セルを消して#DIV/0!×8の事故)
3. 条件付き書式の拡張(x14)は保存時に落ちる(標準ルールは保持される)
4. Windowsコンソール出力はcp932で落ちることがある — スクリプト先頭で `sys.stdout.reconfigure(encoding='utf-8')`
5. 修正後は必ず再計算して数式エラー0件を確認:
   ```bash
   python3 /mnt/skills/public/xlsx/scripts/recalc.py X.xlsx 180
   ```

# v2 事前登録（2026-09-01・第2サイクル）

**v1の診断を受けた設計修正。実行前に確定させたもの。これが最後のインサンプル判定。**

修正はいずれも **v1の結果を見て「良くなる方向」を探したものではなく、

## v2-1. ポジションサイジング（測定装置の修正）

v1の診断で、同日エントリー数が**中央値2件に対し最大117件**（2026-07-16）と判明した。
これを「1トレード=NAV10%固定」で資産曲線に流すと、**実際には建てられない建玉**を
前提にMDDが算出される。v1の -32.3% はその値である。

修正:

- **同時保有ポジション上限 10**（各NAV10%）をハード制約とする
- 枠が満杯なら新規シグナルは**スキップ**（後日に持ち越さない）
- 同日シグナルが空き枠を超える場合は **`score` 降順**で優先採用。
  同点は ticker 昇順で決定的に処理する
- 資産曲線は**この実行可能な建玉のみ**で計算する。
  建玉は entry 時点のNAVの10%を配分し、exit 時に `配分額 × 純リターン` を
  NAVに反映する（実現ベース。v1と同じくマークトゥマーケットはしない）

これは戦略の変更ではなく、**測定装置を実行可能な形に直すもの**。

## v2-2. 市場フィルター（設計の修正）

v1の診断で、市場環境別の期待値が
**上昇相場 +2.40%（1,559件）/ 下降相場 -0.48%（183件）** と分かれた。
ヘッジも市場フィルタも持たないロングオンリー戦略が市場ベータをそのまま
被っている。

修正:

- **TOPIX が200日移動平均を下回る間は新規エントリーを停止**
- **保有中ポジションのエグジット判定は変更しない**（4分岐ルールを維持）
- 200日移動平均は entry_date の**前日までの**終値200本で計算する
  （当日を含めない。当日終値は寄り付き時点で未知）
- **200本に満たない期間は「上回っていることを確認できない」ものとして
  エントリーしない**。価格窓の先頭（2021-09-01〜）から約200営業日は
  この扱いになる

# v3以降への申し送り（2026-09-02、v2実行後に確定）

## 頑健性チェックに MDD を含めること

v2 の頑健性チェックは **期待値と勝率しか対象にしていなかった**。その結果:

- 主セル（shift=0, T-15）の MDD は -13.84% で基準内
- しかし shift=-3 で **-19.41%**、shift=+3 で **-24.06%**
- エントリーを変えると T-10 で **-16.30%**、T-5 で **-24.71%**

期待値と勝率は3本ともプラス・変動1.5ptで安定していたため、
**頑健性チェックは通過してしまった**。合格した MDD は3本のうち
たまたま最良の1本だった。

**v3以降の頑健性チェックは、期待値・勝率に加えて MDD を対象にする。**
条件を振ったときに資産曲線の谷の深さが倍近く動くなら、それは頑健ではない。

具体的な形（v3の事前登録時に確定させること）:

- 発表日 ±3 シフトの **3本すべてで MDD が基準内**
- エントリー T-15/T-10/T-5 の **2つ以上で MDD が基準内**

この申し送りは v2 の判定には遡及適用しない（結果を見てから基準を
変えることはしない）。v2 は「形式的には合格、ただし脆弱」として
記録し、実弾投入はしない。

# v3 事前登録（2026-09-02・シャドウポートフォリオ）

**実装前に確定させたもの。** v3 は**本番ペーパー(v2)と並走するシャドウ**であり、
v2 の判定・記録・パラメータには一切触れない。

## v3-0. なぜシャドウにするのか

v2 は既に前向き検証に入っている。走っている検証の途中で判定関数を変えたら、
**その瞬間に前向き検証の意味が消える**（v2-4 / paper_trading_design §4-1）。
一方で §6-1（単一シグナル銘柄の高スコア化）は放置すべきでない実在の問題。

したがって **同一データ・同一週次で2つのポートフォリオを並走**させ、
成績を前向きに比較する。v2 を止めない、v3 を後出しで有利にしない、の両立。

## v3-1. A1 最低証拠本数ルール

**available なシグナルが3本未満の銘柄は採用しない。**

根拠は §6-1 の実測。合成スコアは available の平均なので、
8本中1本しか available でない銘柄も、その1本の点数がそのまま合成スコアになる
（実例: 1418 が S2 単独で 0.700）。証拠8本の銘柄と1本の銘柄が同じ土俵で
順位付けされ、10枠の優先採用が score 降順である以上、**証拠の薄い銘柄が
枠を取りうる**。

閾値「3本」はデータを見て決めた値ではない。8本中の過半でも1本超でもなく、
「1本の偶然では動かない最小限」として設計上決めた。**結果を見て動かさない。**

## v3-2. B1 集中キャップ

- **同一イベント日の新規エントリー最大5件**
- **同一セクターの同時保有最大3件**

根拠は v1 診断（4-3）。同日エントリーが最大117件、下降相場で期待値が
マイナスに転じる形が出ていた。10枠すべてが同じ日・同じセクターで埋まると、
1つのショックで全部やられる。v2 の10枠制約は「建てられる数」の制約であって
**分散の制約ではない**。

キャップ値（5件 / 3件）も設計上の決め（10枠に対して半分 / 3分の1弱）。
**結果を見て動かさない。**

## v3-3. 記録と分離

- v2 の `forecast_snapshots` / `paper_trades` は**読むだけ。書き換えない**
- v3 は別テーブル `shadow_snapshots` / `shadow_trades` に記録する
- 同一週次バッチの中で、同じ候補集合・同じスコアに対して
  v2 と v3 の採否だけを別々に計算する（**スコアリングは共通**）

## v3-4. 判定方法

- **v2 との成績差分を四半期ごとに記録**する
- **合否は 4〜6四半期後**。短期で判断しない
  （v2 の建玉は年約67件。1四半期では統計的に何も言えない）
- 四半期ごとに見るのは記述統計のみ:
  建玉数・期待値・勝率・MDD・同日集中度・セクター集中度

## v3-5. 変更禁止

v3 の閾値（3本 / 5件 / 3件）は、**前向き検証の途中で動かさない**。
動かしたくなったら v4 として新規に事前登録する。

## 共通事項

- スコアリングは3本とも共通（v2 と同じ `score_ticker`）。**違うのは採否と
  サイジングとエグジットだけ**

## シャドウB（エグジット改善 + スコア連動サイジング）

### B-1. エグジット: 4分岐フル実装

`module_c/exit_engine.decide_exit()` の判断をそのまま使う。

| 分岐 | 条件 | 執行 |
|---|---|---|
| STOP_LOSS | 予測比 売上 < 95% | 全撤退 |
| TP50_TRAIL | 売上ビート + 利益ビート + ガイダンス上方修正 | 50%利確 + **残りT+3トレール** |
| TP_ALL | インライン（売上 ≤105% かつ 利益 95〜105%） | 全利確 |
| EXIT | 上記以外（方向性なし） | 全撤退 |

**TP50_TRAIL の残り50%は T+3** とする。B3 の検証では規則がトレール幅を
定めておらず T+5 の代理実装を使ったが、シャドウBでは **T+3 を初値として
明示的に定める**。データを見て変えない。

### B-2. サイジング: スコア連動

| スコア | ポジション |
|---|---|
| 0.30 以上 | NAV の **15%** |
| 0.15 〜 0.30 | NAV の **10%** |
| 0.10 〜 0.15 | NAV の **5%** |

同時保有上限は v2 と同じ10枠。ただし**合計エクスポージャは 100% を超えない**
（15%が7本入った時点で枠が残っていても新規は建てない）。

### B-3. 依存関係と評価不能の扱い

4分岐は `forecast()` を必要とする。`forecast()` は前年同四半期に依存しており、
制度変更後は大半で使えない（B3 実測: 334件中 評価可能7件 = 2.1%）。

**span-matched 移行が完了するまでは、予測可能な銘柄のみ4分岐で評価し、
評価不能な建玉は件数を記録した上でスキップする**（v3 の skip 記録と同じ扱い）。
スキップを「損益ゼロ」として混ぜない。**評価できなかったことを数える。**

## シャドウC（高閾値版）

- `SCORE_THRESHOLD` を **0.10 → 0.20**
- **他は v2 と完全に同一**（10枠・NAV10%固定・固定T+2エグジット・市場フィルター）

**目的**: 薄いトレードを捨てると質が上がるかの前向き検証。

- **v2 / A / B / C の4本を横並びで比較**

# P3 事前登録・追加検証項目（2026-09-18 確定）

**実装・実行の前に確定させたもの。以下3件は「結果を見てから決める」ことを避けるため、
測る対象と判定方法を先に書き切る。** v2 / シャドウA / B / C の判定・パラメータには触れない。

## P3-1. S1 売上方向ガードの OR / AND（calibration_backlog §32-3）

2026-09-18 に S1 へ売上方向ガードを入れた。「Q単独売上が qoq **または** yoy でプラス」
という指示の文言どおり `sales_direction.MODE = "any"` を既定にしたが、
**OR と AND で結論が変わる銘柄が実在する**（6838 多摩川HD: Q3単独 qoq −16.7% / yoy +17.4%）。
どちらが正しいかは**実データで符号を測ってから決める**。

### 測る対象

同一バックテスト（主セル T-15 × T+2、`SCORE_THRESHOLD=0.10`、コスト往復0.4%控除後）を
**MODE のみを変えて2本**走らせ、差分を見る。他のパラメータは一切動かさない。

| | any（OR） | all（AND） |
|---|---|---|
| 加点側 S1（raw>0）のうち不採用 | 71 / 380 | 189 / 380 |
| up / down / unverified | 678 / 159 / 13 | 421 / 416 / 13 |

（as_of 2026-09-18・universe 3,800 での事前実測。バックテスト期の値ではない）

### 判定方法（先に固定する）

1. **主判定**: S1 が発火に寄与したトレードに限定した1トレード期待値を
   any / all で比較する。**S1 を含まないトレードは両方に等しく入るので判定から外す**
   （含めると差が薄まって何も言えなくなる）
2. **必要条件**: 当該部分集合のトレード数が **両方とも100件以上**。
   下回った側があれば「判定不能」とし、優劣を語らない
3. **副作用の記録**: `sales_qoq_negative` が付いたトレード（OR でのみ通る群）の
   期待値・勝率を単独で記録する。**この群がプラスなら OR、マイナスなら AND** が
   支持される、というのが本検証の核心
4. **MDD**: v3申し送りに従い、期待値・勝率に加え MDD も両方で記録する

### 変更禁止

`sales_direction.MODE` は**この検証が終わるまで `"any"` から動かさない**。
検証の結果 `"all"` を採る場合も、既定の切替は別途ユーザー承認を取る（§31 と同じ手続き）。

## P3-2. 合成スコアの信頼度縮小（採用本数）

`calibration_backlog` §6-1 / §31 / §35 に記録した「採用1本で ±1.0 に張り付く」問題。
**縮小係数 k の導入可否を、k=0（現行）/ k=1 / k=2 の3本で測る。**

    score_adj = (採用シグナルの平均) × n / (n + k)     n = 採用本数

- 主判定は v2 と同じ5項目。**3本すべてで5項目を報告**し、合否は k ごとに独立に出す
- **k の値は結果を見て動かさない。** 0 / 1 / 2 の3点のみ
- 同時に「上位10銘柄の採用本数の中央値」を3本とも記録する
  （現行は中央値1本。縮小の目的はここを動かすことなので、効いたかどうかを直接見る）

## P3-3. S5 の方向判別（補助条件の符号）

§33 で S5 に `guidance_dead`（暗黙の残存四半期利益が負）を実装したが、
**同じ進捗113%が上方修正（6466 TVE）にも通期未達（3441 山王）にも終わっている。**
方向を判別する補助条件を**3本とも記録のみで走らせ、符号を測る**。

| 候補 | 可用率（S5発火483銘柄中） | 備考 |
|---|---|---|
| (a) Q単独OPM の傾き（直近2点） | 482 / 483 = **100%** | ただし両点とも真の span=1 は 129（27%）。残りは累計 span の平均OPM |
| (b) 売上方向ガードの status | 270 / 483 = 56%（up 253 / down 17） | S1 が評価できない銘柄では出ない |
| (c) 業績予想修正の開示（180日以内） | 16 / 483 = **3%** | 決定的だが疎すぎる。TDnet 保持期間の制約（§24） |
| (d) S13 受注（available 行あり） | 167 / 483 = 35% | ほぼ年次。四半期 B/B は作れない（§34-2） |

### 判定方法

- S5 が発火したトレードを、上記 (a)〜(d) それぞれで2群に分け、**群ごとの期待値を記録**する

### A-2. イベント窓

- ベンチマーク: **主 = TOPIX**、副 = ユニバースの日次リターン中央値を累積した指数

  （窓内の出来高で基準が汚れないように）。基準期間の平均が0なら欠測
- 出来高倍率（副）= `出来高(k) / 平均出来高(k−20〜k−1)`（文字どおりの「直近20日平均」）

フェーズAの記述統計（calibration_backlog §37）だけ。v2 / シャドウA〜D の判定・記録・パラメータには触れない。

### B-0. フェーズAから読める制約（事実）

| 分岐 | ユーザー指定の条件 | フェーズAの実測（対TOPIX、t は日付クラスタ） | 読み |
|---|---|---|---|
| 初動利確 | ②大・③小 | 業績修正 ②+2.51%（t 2.06）③+0.72%（t 1.42）/ 配当修正 ②+3.58%（t 3.30）③+0.32%（t −0.15） | **修正を伴う開示では条件に合う** |
| 初動利確 | 同上 | 短信 ②−0.56%（t 0.98）/ 単独の短信 ②−1.14%（t −1.81） | 短信だけの開示では②が大きくない |
| ドリフト保有 | ③が有意 | 全種別で日付クラスタ |t| < 2 | **無条件のドリフトは支持されない** |

注意: フェーズAは**全イベントの母集団**（ベースレート）であって、スクリーナーが証拠で選んだ銘柄の条件付きではない。
修正の**方向（上方/下方）は分けて測っていない**。T+60 は現データでは測れない（TDnet 2026-07-23〜）。

### B-1. 出口の4分岐（判定順を固定）

1. **構造破綻（価格側・毎日判定）**: 保有中に終値が受容帯下限（VAL）を **M=3 営業日連続**で下回ったら、
   3日目の終値で全撤退。決算前でも作動する。他の分岐より優先
2. **テーゼ破綻（証拠側・T+0 の開示で1回だけ判定）**: 開示された四半期（最新の売上タイル・単独 run-rate、
   `sales_direction` と同じタイル規則）で **売上の前年同期比 ≤ 0 または 営業利益の前年同期比 ≤ 0**、
   または同時に**通期営業利益予想の引き下げ**があれば全撤退
   - 「BS の改善が PL に転換した」ことの最低条件は、売上と利益がともに前年を上回ること、と定義する（OR で破綻）。
     AND（両方 ≤ 0 のときだけ破綻）は**副として記録のみ**（P3-1 の OR/AND と同じく、先に決めない）
   - 前年同期比が取れない場合は「判定不能」として件数を数え、破綻扱いにしない（次の分岐へ）
3. **初動利確（T+1 終値）**: 2 に該当せず、T+0 に**業績予想の修正または配当予想の修正**が同時開示された場合（B-0 の1行目）
4. **基準出口（T+2 終値）**: 上記いずれにも該当しない場合。**v2 と同じ**。
   ③が有意でないため、ドリフト保有（T+20）を基準にはしない

- **ドリフト保有（T+20）は記録専用の影のアーム**として、2〜3 に該当しない建玉について T+20 まで保有した場合の
  リターンを併記する（採否には使わない）。T+60 はデータが揃った時点（2026-11 以降）に同じ形で追加する
- 執行日: テーゼ破綻と初動利確の判定には夜間パイプライン（run_daily 19:00/23:15）の XBRL 解析が要る。
  **引け後・休場日の開示 → T+0 の終値、場中・寄前の開示 → T+1 の終値**。バックテスト（EDINET 代理の発表日で
  時刻が無い）では**全件 T+1 の終値**（保守側）
- テクニカル（分岐1）は撤退にだけ使う。**分岐1〜4 のどれもスコアを変えず、候補を足さない**（E-0）

### B-2. 受容帯（簡易ボリュームプロファイル）の計算（パラメータを固定）

| 記号 | 値 | 意味 |
|---|---|---|
| N | **60 営業日** | エントリー日の前営業日までの直近60日（約1四半期）。エントリー日の値は使わない |
| B | **20 本** | 期間中の最安値〜最高値を等幅 20 本の価格帯に分ける |
| X | **70%** | POC（売買代金最大の帯）から、隣接する帯のうち売買代金の大きい方へ1本ずつ広げ、累積が総額の70%以上になった範囲を受容帯とする |
| M | **3 営業日** | 終値が受容帯下限（VAL）を下回る日が3日連続で撤退 |

- 価格は分割調整済み（`adj_factor` による連鎖。フェーズAと同じ）の高値・安値・終値。売買代金は `turnover_value`
- 各日の売買代金は、その日の [安値, 高値] に**一様に配分**して価格帯に積む（高値=安値なら終値の帯に全額）
- 受容帯は**エントリー時に1回だけ計算して保有中は固定**する（価格に追随して帯が動くと割り込みを判定できない）
- 60日分の OHLCV が無い銘柄（上場直後・2021-11 以前のエントリー）は「受容帯なし」として分岐1を適用せず件数を数える
- エントリー時点ですでに終値 < VAL の建玉は `entry_below_val` として記録する。**分岐1 はそのまま適用する**
  （実質的にエントリー後3日での撤退になる。veto として働くことを隠さない）
- Market Profile の慣例（値域の70%）と四半期の長さから決めた値で、データを見て決めたものではない。**結果を見て動かさない**

### B-2b. ユーザー承認（2026-09-20）と、その記録

**承認: 実装とインサンプル測定に進む / 株価・TOPIX の日次更新を run_daily に追加する /
テーゼ破綻は OR（売上か営業利益のどちらかが前年割れで撤退）を採用する。**

OR を採る理由（ユーザーの判断。記録として残す）:

1. テーゼの定義は「BS に積まれた証拠が PL に転換する」であり、**営業利益が前年割れなら転換は起きていない**
2. 実例 3441 山王の Q4単独は売上 4,481百万円（四半期で最大）だが営業損失 −266.3百万円。
   **OR なら撤退、AND なら残留**となり、OR の方が正しく守った
3. **入口と出口は非対称でよい。** 誤った出口は上値を失うだけだが、誤った入口は資本を失う

AND は比較用の記録に留める（B-1 の 2 のまま）。

**申し送り（測定後に再検討・ユーザー指示）**: エントリー時点ですでに受容帯下限を下回っている建玉が
実質3営業日で撤退になる件。設計原則ではテクニカルは拒否（veto）ができるので、本来は
**「受容帯の下にあるなら入らない」が正しい**。ただし**同一トレード集合での比較を優先**し、
今回は現行設計（分岐1をそのまま適用）のまま測る。

- `entry_below_val` の**件数と、その建玉が払った往復コスト**を必ず記録する
- 測定後に **veto 化（該当銘柄をエントリーしない）へ変更するかを判断**する。変更する場合は新規事前登録

**通期予想の引き下げ（B-1 の 2 の第3条件）は、バックテストでは判定不能**。
`projection.db.company_forecasts` は 2026-07-23 以降しか無く、2021〜2026 の建玉には前後比較する予想が無い。
**件数を「判定不能」として数え、(a)(b) の前年比だけで判定する**（前向きのシャドウEでは使える）。

**T+60 は現データでは測れない**（TDnet 2026-07-23〜）。**2026年11月頃にデータが揃った時点で、
本節の定義のまま再測定する**。それまで T+20 の記録アームだけを持つ。

### B-3. 測り方（実装承認後。結果を見て変えない）

1. **インサンプルの符号測定（記述のみ・合否なし）**: v2 と同じ建玉集合（主セル T−15、shift 0、10枠、市場フィルター）に対し、
   - E0: v2 そのまま（固定 T+2）
   - E1〜E3: E0 に分岐1だけ / 分岐2だけ / 分岐3だけを足したもの
   - E4: 分岐1〜4 の全部
   を並べ、v2 と同じ5項目（期待値・勝率・TOPIX超過・MDD・上位5集中）と、分岐ごとの作動件数・判定不能件数を記録する。
   ±3シフトの3本すべてで同じ表を出す（v3申し送りに従い MDD を含める）
2. **判定の形**: 「E4 − E0 の期待値差の符号が ±3シフトの3本で一致するか」を記録する。一致しなければ「符号不定」。
   **1群100件未満の分岐は判定不能**（§4）
3. **前向き**: 1 の結果をユーザーに報告し、承認を得てから `shadow_trades` の `variant='E'` として並走させる。
   それまでは本番・シャドウA〜D のいずれにも接続しない
4. 前提: 前向き記録には日次の株価（OHLCV）と TOPIX の更新が要る。現状 run_daily に入っていない（§37）

# シャドウF 事前登録（2026-09-20）—— 受容帯とテーゼ破綻を**入口側**で使う

**測定の前に確定させたもの。** シャドウE（出口）とは別件として立てる。
E の測定（calibration_backlog §39）で分かったのは次の2つで、本節はその2つを
**出口ではなく入口で使ったらどうなるか**だけを測る。

- 受容帯下限割れは**負け建玉を選別している**（作動群の E0 期待値 −0.029 / −0.024 / −0.050）。
  ただし**割れてから3日目に売ると更に悪化**する（−0.023 / −0.021 / −0.019）
- テーゼ破綻（OR）は**識別力がある**（健全 +0.042 / +0.031 / +0.039 対 破綻 −0.007 / +0.002 / −0.016）。
  ただし出口を T+2 → T+1 に早めても損益はほぼ動かない（±0.0006）

**E-0 の設計原則は変わらない。** テクニカル（受容帯）は**拒否とサイジングにしか使わない**。
候補の追加もスコアへの加点もしない。F-1 は「入れない／小さく入れる」だけで、
スコアの順位には触れない（`score` を書き換えない構造にする）。

## F-0. 共通

- 建玉の選択は v2 と同じ規則（T−15 エントリー・10枠・score降順・市場フィルター）。
  **F が変えるのは「その候補を採るか／いくら張るか」だけ**
- 出口は **v2 と同じ固定 T+2**（E の測定で 4分岐が悪化と出たので、入口の効果だけを見る）
- 同一建玉集合の比較ではない（入口を変えれば建玉が変わる）。**枠の空き方まで含めて v2 の
  simulate をそのまま使い、採否の判定だけ差し替える**
- ±3シフト3本すべてで実施。**判定は「F* − v2 の期待値差の符号が3本で一致するか」のみ**
- 1群100件未満は判定不能（§4）。合否は出さない。**記述統計と符号の記録まで**

## F-1. 受容帯を入口で使う（拒否・サイジング）

エントリー日の**前営業日まで**の受容帯（E-B B-2 と同じ N=60 / B=20 / X=70%。**動かさない**）を使う。

| 変種 | 規則 |
|---|---|
| F1a 拒否 | エントリー日の終値が **VAL 未満**なら**建てない**（枠は次の候補に回る） |
| F1b 半分 | VAL 未満なら **NAV 5%**（通常の半分）で建てる。VAL 以上は通常どおり 10% |
| F1c 帯内のみ | 終値が **VAL 以上 VAH 以下**のときだけ建てる（VAH 超も建てない） |

- 位置の判定は**エントリー日の終値**（受容帯はその前日までで作る。当日の値は帯に入れない）
- F1c を入れるのは、「帯の上（買われ過ぎ）」と「帯の下（崩れ）」を分けて測るため。
  **どちらが悪いかを結果を見てから選ばない**ように、3変種を同時に登録して同時に出す
- サイジングの 5% は v2 の 10% の半分。シャドウB の 15/10/5% と同じ刻み。**結果を見て動かさない**

## F-2. テーゼ破綻を入口の除外条件に使う

**前回の決算で BS→PL 転換が起きていなかった銘柄を、次の決算では買わない。**

| 変種 | 規則 |
|---|---|
| F2a | エントリー日（T−15）時点で**直近に開示済みの四半期**が「テーゼ破綻」なら建てない |
| F2b | 直近**2四半期連続**で破綻なら建てない（1回の不振では外さない） |

- 破綻の定義は E-B B-1 の分岐2 と**同一**（売上 or 営業利益が前年同期比 ≤ 0。OR。
  run-rate の差で比較し、前年が負でも壊れない）。**入口では T−15 時点の PIT で判定する**
  （出口の分岐2 は T+0 の開示を見る。**同じ規則を別の時点に当てる**）
- 判定不能（前年同期が取れない）は**建てる**（除外しない）。件数を記録する
- **これは証拠側の条件であってテクニカルではない。** F-1 と分けて測り、合算しない

## F-3. 記録するもの

各変種について、v2 と同じ5項目（トレード数・期待値・TOPIX超過・MDD・上位5集中）と、
**除外件数 / サイジングを下げた件数 / 判定不能件数**、および「除外した候補が実際どうなったか」
（除外しなかった場合の E0 リターン）を記録する。**除外が正しかったかを後から検証できるようにする。**

## F-4. 変更禁止

N=60 / B=20 / X=70% / サイジング 5% / 2四半期 は**初値であり、結果を見て動かさない**。
動かしたくなったら新規事前登録（v3-5 と同じ手続き）。

# シャドウG 事前登録（2026-09-20）—— S5 は上方修正を先行して当てるか

**測定の前に確定させたもの。** S5（進捗率・死んだガイダンス）が「この会社は予想を上げる」を
先に言えているかを、**実際の修正開示の方向**で答え合わせする。
`guidance.revision_direction` が実データで埋まったので初めて測れるようになった（calibration_backlog §41）。

**これは記述統計であり、シグナルではない。** 結果でスコア・採否・出口を変えない。
v2 / シャドウA〜D / E / F には触れない。

## G-0. なぜ測るのか

§33 で S5 を本番化したとき、**同じ進捗113%が上方修正（6466 TVE）にも通期未達（3441 山王）にも
終わっていた**。P3-3 に「符号を測る」と登録したが、当時は修正開示の方向が1件も取れず測れなかった。
S5 の主張は「進捗が期待を超えている会社は、会社自身が予想を上げる」。その的中率をベースレートと比べる。

## G-1. 窓とイベント（固定する）

| 項目 | 定義 |
|---|---|
| S5 発火日 | 週次スキャンの as_of ではなく、**各銘柄の S5 が available かつ score>0 になった判定日**。判定は `span_runner.score_ticker(policy="evidence_strict")` を **as_of = 判定日**で行う |
| 判定日の集合 | 2026-07-23 〜 2026-09-18 の**各週の月曜**（TDnet アーカイブが始まった週から。休場なら翌営業日）。9週 |
| 追跡窓 | 判定日から **90 暦日以内**（`disclosed_at` の日付で判定。T+0 の営業日調整はしない） |
| 結果 | 窓内の **業績予想の修正開示**（`filings.subtype='業績予想修正'`）のうち、`guidance.revision_direction`（営業利益・通期）が **up / down / flat**。方向が取れない開示は **unknown** として別に数える |
| 修正なし | 窓内に修正開示が無ければ **none** |

## G-2. 比較するベースレート（先に定義する）

- 分母は「その判定日に**スコアが計算できた**銘柄」ではなく、**ユニバース全体**とする。
  S5 が評価できない銘柄を分母から外すと、比較対象が「評価できる会社」に偏る
- 判定日ごとにベースレートを出し、**判定日で重み付けしない単純平均**と、
  **のべ銘柄日での割合**の両方を報告する（どちらかを後から選ばない）

## G-3. 群の分け方（先に固定する）

| 群 | 定義 |

1. 群ごとの **up / down / flat / unknown / none の件数と割合**
2. **up の割合 − ベースレートの up の割合**（差と、その95%信頼区間。二項の正規近似）

## G-5. 既知の限界（実行前に分かっているもの）

# シャドウH 事前登録（2026-09-20）—— 上方修正の初動を「ギャップ」と「寄付後」に分解する

**測定の前に確定させたもの。** §41 で修正の方向が実データで埋まり、
**上方修正の初動 +4.78%（日付クラスタ t 3.91・n=61）**が出た（§38 E-A2-2）。
その +4.78% が**寄付前に終わっているのか、寄付後にも残るのか**を分ける。

## H-0. 何を分けるのか

T+0 は Phase A（E-A1b）の定義そのまま（引け後・休場日の開示は翌営業日）。

| 量 | 定義 |
|---|---|
| ギャップ | `始値(T+0) / 終値(T−1) − 1` |
| 寄付後 | `終値(T+0) / 始値(T+0) − 1` |
| 寄付から翌日引け | `終値(T+1) / 始値(T+0) − 1` |
| 初動（既報） | `終値(T+1) / 終値(T−1) − 1`（②と同じ。分解の合計と一致するか検算する） |

価格は分割調整済み（各行の `adj_close / close` を始値・高値・安値に掛ける。フェーズAと同じ）。

## H-1. ベンチマーク（先に決める）

TOPIX は終値しか無く**ギャップと寄付後に分けられない**。そこで
**ユニバース中央値**を使う（フェーズAの副ベンチマークと同じ考え方）:

- その日のユニバース（`universe_flag=1`・当日と前日に約定がある銘柄）の
  **始値/前日終値の中央値**を「市場のギャップ」、**終値/始値の中央値**を「市場の寄付後」とする
- 相対値 = 個別 − 市場中央値（差で取る。比ではない）
- **対TOPIX は全日ベース（既報の②）でのみ併記**する。分解の相対化には使わない

## H-2. 層別（先に固定する）

1. 開示時刻の区分（場中 / 引け後 / 場外 / 不明）。**不明の件数を必ず報告する**
2. 方向（上方 / 下方 / 不明）。主対象は**上方**
3. ストップ高・寄らずの扱い:
   - `高値(T+0) == 安値(T+0)` を「**値幅なし**」として数える（1本値。比例配分・寄らずストップ高を含む）
   - `始値(T+0) == 高値(T+0)` かつ 寄付後リターン ≤ 0 を「**寄り天**」として数える（参考）
   - 値幅なしの建玉は**寄付で入れたとみなせない**ので、寄付起点の集計から**除外し、件数を明記**する

## H-3. 統計

各量について n・中央値・四分位・平均・正の割合・t（素朴 / T+0 日付クラスタ）。
**1群30件未満は「件数不足」と注記**（E-A と同じ）。

## H-4. 判断の分岐（先に書いておく。結果でこの基準を動かさない）

- **ギャップが初動のほぼ全部（寄付後の中央値が概ねゼロ、日付クラスタ t が |t| < 2）**なら、

- **寄付後にも中央値プラスが残り、日付クラスタ t ≥ 2**なら、予測せず反応速度で取りうる

この2つのどちらかを**報告する**。どちらを採るかの判断はユーザーが行う。

## H-5. 既知の限界

- 上方修正 61件（下方 11件・不明 196件）。**下方と不明は件数不足または方向不明**
- 始値は J-Quants の `O`。**寄り付かなかった日でも前日終値等が入る可能性**があるため、
  値幅なし（高値=安値）と出来高0を別に数えて報告する

## J-3. R の水準別（**診断のみ・閾値は動かさない**）

R を **1.0–1.1 / 1.1–1.3 / 1.3–1.5 / 1.5–2.0 / 2.0+**（および 1.0 未満）に分け、層ごとに:

- **precision** = その層の観測のうち窓内に up が出た割合
- **recall** = 窓内に up が出た観測全体のうち、その層が占める割合

**1.30 は開示義務（+30%）から導いた値であり、この表を見て動かさない。** 記録のみ。

## J-4. 「保守的な会社」の検証

過去中央値進捗率が **100%超**の銘柄（実測: 3Q 48社 / 2Q 11社 / 1Q 3社）について、
**上方修正の発生率が他の銘柄より高いか**を同じ枠組みで測る。

- 群分けは**判定日時点で計算できる過去中央値進捗率**（PIT）で行う。当期の四半期に対応する値を使う
- 100%超 / 90–100% / 90%未満 の3群 + 全体。**1群100件未満は判定不能**
- これは §51 の申し送り（「保守的な予想を出す」と「実際に上方修正する」は同じか）への回答になる

## J-5. 限界（実行前に分かっているもの）

- `fins_summary` は Light の5年ローリング。**2021-09-21 より前は無い**
- 修正イベントは**予想値の変化**で検出する。会社が予想を据え置いたまま実績が乖離した場合は入らない
- 決算と同時の予想変更も「修正」に数える（**開示の種類で区別しない**）。
  §46 で見た「S5 が評価可能な銘柄は直近に決算を出した銘柄」という偏りは、
  母集団を揃えることで部分的にしか消えない。**判定日クラスタの t を併記して読む**

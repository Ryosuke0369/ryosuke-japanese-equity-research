# DCFモデル フォーマット標準メモ(5726版を正とする)

作成: 2026-08-26。5726_DCF_Model_20260826.xlsx(template rev e5effd6 + 手修正)を今後の標準フォーマットとして記録する。
格納先推奨: リポジトリ docs/。手順書v2の付属文書として扱う。

## 1. シート構成(8枚、この順)

1. **Executive Summary** — 現値・Target(DCF Mid)・判定・手法別バリュエーション表・投資テーゼ3行・リスク3行。テーゼとリスクは数式連動の文章(TEXT関数で現値・倍率・WACCを埋め込む)にする
2. **Financial Statements** — 実績5期(PL要約・CF・BSハイライト)。粗利率/OPM/成長率は数式。データ欠損時は注記行に明示
3. **DCF Model** — Assumptions(全て根拠付き)→WACC→5年FCF→PGM法→Exit法→シナリオ入力マトリクス(5本×成長率/COGS率/SGA率)。シナリオはC27の1セル切替(CHOOSE参照)
4. **Reverse DCF** — 今回の最大の発明。Block A(即時到達の必要定常OP)/Block B(到達年数N×WACCのマトリクス、閉形式)/Block C(必要利益を売上×マージンに分解)/Block D(倍率表現)/Block E(取引ベンチマーク)/Block F(一行回答、数式連動文章)。全セルが他シートへの生きた数式
5. **NWC Schedule** — DSO/DIH/DPOの日数ドライバー方式、シナリオ別日数マトリクス付き。在庫重量級ビジネスではFCF最大のスイングファクターになるため独立シート必須
6. **Comps Analysis** — 対象行は生きた数式、ピア行は取得日明記の静的値。統計(25/50/75パーセンタイル)はピア行のみ。除外行は削除せず残置+Note+統計から除外(東邦方式)。正常化純利益の参考行を持つ
7. **Sensitivity Analysis** — Table1: WACC×永久成長率、Table2: WACC×Exit倍率、Table3: 為替感応度(該当銘柄のみ)。ヘッダは現在値中心に自動追随
8. **Adjustments Log** — 全推定・全設計判断・全手修正を「日付/セル/変更内容/理由/元の値/状態」で記録。状態は{確定/設計判断/推定/要確認/未解決/DRAFT}。末尾にPipeline Metadata(validate_output.py用、編集禁止)

## 2. 守るべき規約

- **Target(DCF Mid)はPGMとExitの2本平均のみ。CompsはTarget不算入**、[参考]表記で残す(3905・5726で確立した原則)
- 逆算DCFの一行回答(Block F)を必ず出す: 「現値は何を・何倍・何年で織り込んだ価格か」
- 分母が歪んだ指標(特損・シクリカル底・解約済み契約)は削除でなく「残置+除外+理由記録」
- 推定セルは全てAdjustments Logに記録、会社未開示の前提(稼働時期・感応度比率など)は「推定・要確認」で明示
- 負債過大な銘柄ではEV<ネットデットで株式価値が負になる: 表示は0下限(オプション価値)の注記を付ける
- 納品は常にDRAFT、ユーザー検証・手修正の記録後にFINAL化(手順書v2 §6-3)
- 手修正の記録はPipeline Metadataブロックの後ろに追記(メタデータを崩さない)

## 4. 銘柄タイプ別の使い分け(5銘柄+5726の教訓)

- **物語先行型(3905型)**: DCFはDownside測定と逆算が主。SOTPは前提崩壊で参考値化しうる
- **シクリカル型(5726型)**: ミッドサイクル正常化+逆算が主。Compsはディール汚染・底分母に注意。NWC(在庫日数)がFCFを支配
- **希少性/イベント型(5726で発見)**: DCFで説明できない価格差=プレミアムの値段として定量化する。取引ベンチマーク(Block E)が代替アンカー
- **継続企業注記型(6217型)**: DCF以前に見送り判定が先

## 5. 新規銘柄プロンプトの作り方(新チャット/ClaudeCode用の自己完結手順)

新しい銘柄のDCFプロンプトを作るとき、本メモ+以下の入力があれば§1-2のフォーマットで自動生成できる。

### 必須入力(ユーザーが供給)
- 決算短信の数値: 通期PL3期以上+直近四半期PL、BS要点(現金・借入・棚卸・建設仮勘定・純資産)、CF計算書(営業/投資/財務、有形固定資産取得)
- 基準情報: 分析日の株価、発行済株式数(→時価総額・ネットデット・EVを冒頭で計算)
- 会社予想とコンセンサス(あれば)

### あれば精度が上がる入力
- セグメント注記(→セグメントブリッジ生成の条件)
- 支払利息実額(→実績ベース負債コスト。5726では推定2.8%→実績0.85%でWACCが0.4pt動いた)
- 決算説明会・IR発言の質的情報(→シナリオの根拠、5726ではキオ君要約が為替/前倒し/高機能材料の分解に直結した)
- 為替前提・輸出比率(→Table3為替感応度の条件)

### プロンプト雛形の骨格
1. 依頼: 「<コード> <社名>のDCFモデル生成。出力名 <コード>_DCF_Model_<日付>.xlsx。手順書v2準拠、DRAFT納品」
2. 企業コンテキスト: 事業・需要ドライバー・銘柄タイプ(§4のどれか)・直近決算の質的分解
3. 基準情報+入力財務データ(表で転記)
4. モデル要件: §1の8シート+§2の規約を明記。銘柄固有の必須要件(逆算の問いの立て方、Comps汚染注意、正常化項目)を追加
5. 出力: Excel+3行サマリー(Target・逆算結果・最大リスク)、推定は全てAdjustments Log

### 検証時のチェック順(chat側Claudeの仕事)
recalcエラーゼロ → 主要計算のスポットチェック(EV・逆算閉形式・Comps再構成) → 外部事実の裏取り(ピアの上場状態・比率) → 規約違反の検出(Target構成・分母歪み) → 手修正リスト提示 → 修正はAdjustments Logに記録 → ユーザー確認後にFINAL化
